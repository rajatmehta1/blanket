1. High-Level Pipeline Overview


User runs:  blanketaudit scan ./my-repos --format pdf,html --framework hipaa

scan()                          # cli/main.py — parses CLI args
  → _run_scan()                 # cli/main.py — creates pipeline, calls run()
    → AuditPipeline.build()    # orchestrator/pipeline.py — wires all stages
    → AuditPipeline.run()     # orchestrator/pipeline.py — executes stages in order
      → ingest_node()          # indexes all files in repos
      → triage_node()          # scores files, assigns tiers
      → estimate_node()        # projects LLM cost
      → static_node()          # semgrep + gitleaks + osv
      → security_node()        # SecurityAgent.execute()
      → compliance_node()      # ComplianceAgent.execute()
      → architecture_node()    # ArchitectureAgent.execute()
      → quality_node()         # QualityAgent.execute()
      → validate_node()        # 4 hallucination gates
      → score_node()           # risk scoring + health grade
      → report_node()          # ReportAssembler.assemble()
      → manifest_node()        # records scan metadata
  → _output_results()          # cli/main.py — generates PDF/HTML/JSON files

AuditPipeline.ingest_node(state)
orchestrator/pipeline.py

For each repo source in the state, calls FileIndexer.index_project() to scan and catalog every file.

→ state["files"] = list[FileMetadata]
FileIndexer.index_project(repo_path, repo_name)
ingestion/file_indexer.py

5. Stage 3: Triage & Cost Estimation

AuditPipeline.triage_node(state)
orchestrator/pipeline.py

Orchestrates file scoring and tier assignment. Determines which files get full AI analysis vs static-only.

FileScorer.score_all(files) → dict[str, int]
triage/file_scorer.py

Scores each file 0-100 based on: language weight (Python/Java=15), file type (SOURCE=10), security patterns (auth/payment=+15), handler patterns (+10), recency (+5), import fan-out (+10). No LLM used.

TierAssigner.assign(files, scores) → dict[str, int]
triage/tier_assigner.py

Maps scores to tiers: Tier 1 (score > 75) = full AI + all policies. Tier 2 (50-75) = static + light AI. Tier 3 (< 50) = static only, zero LLM calls.

CostEstimator.estimate(files, tiers) → CostEstimate
orchestrator/cost_estimator.py

Projects total token usage (file_bytes/4 + overhead) and dollar cost per agent. Used by --dry-run to show cost before spending. If over budget, pipeline aborts here.

6. Stage 4: Static Analysis Tools

AuditPipeline.static_node(state)
orchestrator/pipeline.py

Runs 3 external tools on each repo, then normalizes all raw tool output into AuditFinding objects with source="static".

run_semgrep(repo_path) → list[dict]
agents/tools/semgrep_tool.py

Runs Semgrep SAST with security rulesets. Returns raw findings with rule_id, severity, file, line, code snippet.

run_gitleaks(repo_path) → list[dict]
agents/tools/gitleaks_tool.py

Scans for hardcoded secrets (API keys, passwords, tokens) in code and git history.

run_osv_scan(repo_path) → list[dict]
agents/tools/osv_tool.py

Checks dependency manifests (package.json, requirements.txt) against the OSV vulnerability database for known CVEs.

7. Stage 5: AI Agent Execution (4 Agents)

All 4 agents follow the same Template Method Pattern defined in BaseAgent. The pattern is: static checks FIRST → AI enrichment SECOND.

BaseAgent Template (inherited by all 4 agents)

BaseAgent.execute(state) → list[AuditFinding]
agents/base_agent.py

Template method: (1) call run_static_checks(), (2) check _should_run_ai(), (3) if yes, call run_ai_analysis() with static candidates. Never raises — catches all errors and falls back to static-only.


# BaseAgent.execute() pseudo-code (agents/base_agent.py)

async def execute(self, state):
    # Step 1: Always run static checks (deterministic, no LLM)
    candidates = await self.run_static_checks(state)

    # Step 2: Should we invoke AI?
    if not self._should_run_ai():
        return candidates  # static-only fallback

    # Step 3: Send static candidates to LLM for enrichment
    prioritized = self._prioritize_for_ai(candidates)
    ai_findings = await self.run_ai_analysis(state, prioritized)

    return ai_findings
4 Agents Run (sequentially or in parallel)

Security Agent

agents/security_agent.py

Static: Semgrep SAST + Gitleaks secrets + OSV CVEs
AI: Filters false positives, adds blast radius, generates fix code, maps to compliance controls

Compliance Agent

agents/compliance_agent.py

Static: Policy YAML regex/AST checks + Milvus RAG search
AI: Maps code to regulatory controls (HIPAA/SOC2/PCI/GDPR), classifies PASS/PARTIAL/FAIL

Architecture Agent

agents/architecture_agent.py

Static: Builds dependency graph, detects circular deps, infers layers, finds God classes
AI: Assesses coupling, suggests refactoring, estimates layer improvements

Quality Agent

agents/quality_agent.py

Static: Cyclomatic complexity, dead code, silent exceptions, long functions, coverage
AI: Estimates tech debt hours, prioritizes refactoring, assesses maintainability

8. Stage 6: Hallucination Validation (4 Gates)

Every AI-generated finding passes through 4 sequential gates. A finding that fails a gate is either rejected or downgraded.

ValidationPipeline.validate(findings, repo_files)
validation/pipeline.py

Orchestrator that runs each finding through all 4 gates in order. Static-only findings skip Gates 2-4.

Gate 1: SchemaGate.validate(raw_dict)
validation/gate_schema.py

Parse & Validate: Converts raw dict → Pydantic AuditFinding. Validates control IDs exist in the whitelist. Rejects malformed findings.

Gate 2: EvidenceGate.validate(finding, repo_files)
validation/gate_evidence.py

Reality Check: Verifies file_path exists in the repo, line numbers are within bounds, and code_snippet matches actual file content (≥80% fuzzy match).

Gate 3: ConfidenceGate.validate(finding)
validation/gate_confidence.py

Confidence Filter: If confidence < 0.7, marks finding as REVIEW_NEEDED. Never rejects — just flags for human review.

Gate 4: CorroborationGate.validate(all_findings)
validation/gate_corroboration.py

Cross-Check: Critical severity from a single agent → demoted to high. Criticals need confirmation from 2+ agents.

9. Stage 7: Scoring & Report Assembly

ReportAssembler.assemble(state) → AuditReport
scoring/report_assembler.py

Master orchestrator for report data. Calls merger, scorer, planner, and summary generator, then packages everything into the final AuditReport Pydantic model.

FindingMerger.merge(findings) → list[AuditFinding]
scoring/finding_merger.py

Level 1 (Exact Dedup): Same file + line_start + line_end + category = one finding (keep highest confidence).
Level 2 (Root-Cause): Same policy_id + category = one representative with affected_locations[].

RiskScorer.score(findings, frameworks) → HealthScore
scoring/risk_scorer.py

Computes 8 category scores using: 100 - (critical×25 + high×10 + medium×3 + low×1). Weighted composite: Security 35%, Compliance 30%, Quality 15%, Performance 10%, Infra 10%. Grade: A≥85, B≥70, C≥50, D≥30, F<30.

RemediationPlanner.plan(findings, health_score) → list[RemediationPhase]
scoring/remediation_planner.py

Builds a 3-phase roadmap:
Phase 1 (Days 1-14): All critical + top 5 high
Phase 2 (Days 15-45): Remaining high + top 10 medium
Phase 3 (Days 46-90): Remaining medium + all low
Each task has estimated effort hours and score impact ("+4 points").

ReportAssembler._generate_summary() → ExecutiveSummary
scoring/report_assembler.py

Generates 2 AI paragraphs + 3-5 immediate action items. Falls back to a template-based summary if LLM is unavailable.

Policy Engine (Used by Agents)

PolicyEngine.load_policies(policy_dir, categories, frameworks)
policies/engine.py

Recursively loads all *.yaml policy files from the policy directory, validates each against the policy schema, and filters by category (security/compliance/architecture/quality) and active frameworks (HIPAA/SOC2/PCI-DSS).

validate_policy_dict(policy_dict)
policies/schema.py

Validates a policy YAML dict against the JSON schema: checks required fields (id, name, severity, category), validates static_checks patterns, and ensures ai_analysis instructions are present.

Dual-Layer Pattern: Each policy YAML has both static_checks (regex/AST patterns that run deterministically) and ai_analysis (instructions for LLM contextual reasoning). Static always runs first. AI only runs if LLM is available and budget allows.
