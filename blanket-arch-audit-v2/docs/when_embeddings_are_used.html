Code Flow Embeddings Guide

When Are Embeddings Used?

Embeddings are only used by the Compliance Agent for semantic search (RAG) against compliance clause databases via Milvus. If you're not running compliance scans, you don't need them at all.

How Embeddings Fit in the Pipeline

Compliance Agent — Semantic Search (RAG)

The compliance agent embeds code snippets and compliance clause text into vectors, then uses similarity search in Milvus to find which code sections relate to which compliance controls (e.g., HIPAA §164.312, SOC2 CC6.1, PCI-DSS Req 6.5).

Code snippet → Embedding model → Vector → Milvus similarity search → Matching compliance clauses

Key point: The other three agents (Security, Architecture, Quality) do not use embeddings. They rely on static tools (Semgrep, Gitleaks, OSV, AST) + direct LLM prompting.

Do You Need Embeddings?

Scan Type Command Example Embeddings?
Security + Architecture + Quality only blanketaudit scan ./repo --domain fintech NOT NEEDED
With compliance framework(s) blanketaudit scan ./repo --framework hipaa NEEDED
Multiple frameworks blanketaudit scan ./repo --framework hipaa soc2 pci-dss NEEDED
Static-only mode (no AI) BLANKETAUDIT_LLM__PROVIDER=none blanketaudit scan ./repo NOT NEEDED
Compliance agent disabled Set agents.compliance.enabled: false in audit.yaml NOT NEEDED

Embedding Provider Options

When you do need embeddings, you have four choices. Two are free and run locally.

Provider Model Cost Notes
HuggingFace all-MiniLM-L6-v2 FREE Runs on your CPU. No API key. No network needed.
Ollama nomic-embed-text FREE Requires Ollama running (local or remote laptop).
OpenAI text-embedding-3-small PAID Requires OPENAI_API_KEY. Fast, high quality.
Voyage voyage-3 PAID Requires Voyage API key. Code-optimized embeddings.

Configuration Examples

Option 1: No embeddings needed (no compliance scan)

If you're only running security/architecture/quality scans with Groq, leave embeddings off:

# .env
BLANKETAUDIT_LLM__PROVIDER=groq
BLANKETAUDIT_LLM__MODEL=llama-3.3-70b-versatile
# No embedding config needed — defaults to "none"

Option 2: Local HuggingFace embeddings (free, no API)

Best for compliance scans when you don't want any external API dependency:

# .env
BLANKETAUDIT_LLM__PROVIDER=groq
BLANKETAUDIT_LLM__MODEL=llama-3.3-70b-versatile
BLANKETAUDIT_EMBEDDING__PROVIDER=huggingface
BLANKETAUDIT_EMBEDDING__MODEL=all-MiniLM-L6-v2
First run: HuggingFace will download the model (~80 MB) once, then it's cached locally.

Option 3: Ollama embeddings on a remote laptop

Use this if you already have Ollama running on another machine:

# .env
BLANKETAUDIT_LLM__PROVIDER=ollama
BLANKETAUDIT_LLM__MODEL=llama3.1
BLANKETAUDIT_LLM__BASE_URL=http://192.168.1.50:11434
BLANKETAUDIT_EMBEDDING__PROVIDER=ollama
BLANKETAUDIT_EMBEDDING__MODEL=nomic-embed-text

# On the remote laptop, pull the embedding model too:
# ollama pull nomic-embed-text

Option 4: Mix providers (Groq LLM + local embeddings)

Use Groq for fast LLM inference, and free local embeddings for compliance RAG:

# .env
BLANKETAUDIT_LLM__PROVIDER=groq
BLANKETAUDIT_LLM__MODEL=llama-3.3-70b-versatile
BLANKETAUDIT_EMBEDDING__PROVIDER=huggingface
BLANKETAUDIT_EMBEDDING__MODEL=all-MiniLM-L6-v2

This is the recommended setup if you want compliance scans without paying for embedding APIs.

TL;DR

No --framework flag? Skip embeddings entirely. You're good.
Using --framework? Pick HuggingFace (free, local) or Ollama (free, on your remote laptop).
Want best quality? OpenAI text-embedding-3-small is fast and accurate, but costs money.
