Docker Deployment Guide ops

Deploy BlanketAudit as a CLI container, an API server, or a full stack with Neo4j, Milvus, and the web UI. Choose the deployment model that fits your team.

Quick Start: CLI in Docker

The simplest deployment. Mount your project directory and get a report.

# Build the CLI image
docker build -t blanketaudit .

# Scan a local project
docker run --rm \
  -v $(pwd)/my-project:/repo \
  -v $(pwd)/reports:/output \
  blanketaudit scan /repo --output-dir /output

# Scan with Ollama (host network for localhost access)
docker run --rm --network host \
  -e BLANKETAUDIT_LLM__PROVIDER=ollama \
  -e BLANKETAUDIT_LLM__MODEL=llama3.1 \
  -v $(pwd)/my-project:/repo \
  blanketaudit scan /repo

# Dry run (cost estimate only)
docker run --rm \
  -v $(pwd)/my-project:/repo \
  blanketaudit scan /repo --dry-run
Note: The CLI image includes Semgrep, Gitleaks, Tree-sitter grammars, and WeasyPrint with all required system libraries. No additional setup needed.

API Server Deployment

Run BlanketAudit as a FastAPI service that accepts scan requests via HTTP. Ideal for integrating with CI/CD pipelines, dashboards, and automated workflows.

# Build the API image
docker build -f Dockerfile.api -t blanketaudit-api .

# Run the API server
docker run -d \
  --name blanketaudit-api \
  -p 8000:8000 \
  -e BLANKETAUDIT_LLM__PROVIDER=anthropic \
  -e ANTHROPIC_API_KEY=sk-ant-... \
  -v blanketaudit-data:/data \
  blanketaudit-api

# API docs available at:
# http://localhost:8000/docs     (Swagger UI)
# http://localhost:8000/redoc    (ReDoc)

Key API endpoints:

MethodEndpointDescription
POST/api/scanStart a new scan (async, returns scan ID)
GET/api/scan/{id}Get scan status and results
GET/api/scan/{id}/reportDownload report (PDF/HTML/JSON/SARIF)
GET/api/scansList all scans with history
POST/api/scan/estimateDry-run cost estimate
GET/api/healthHealth check + provider status
GET/metricsPrometheus metrics endpoint

Full Stack (docker-compose)

The complete BlanketAudit platform: API server, Neo4j for call graphs, Milvus for semantic search, PostgreSQL for scan history, and the Next.js web UI.

# Start the full stack
docker compose up -d

# Services:
#   API:     http://localhost:8000
#   Web UI:  http://localhost:3000
#   Neo4j:   http://localhost:7474 (browser) / bolt://localhost:7687
#   Milvus:  localhost:19530
#   Postgres: localhost:5432

# View logs
docker compose logs -f api

# Stop everything
docker compose down

docker-compose.yml

version: "3.9"

services:

  # ── BlanketAudit API Server ──
  api:
    build:
      context: .
      dockerfile: Dockerfile.api
    ports:
      - "8000:8000"
    environment:
      - BLANKETAUDIT_LLM__PROVIDER=anthropic
      - ANTHROPIC_API_KEY=${ANTHROPIC_API_KEY}
      - BLANKETAUDIT_EMBEDDING__PROVIDER=openai
      - OPENAI_API_KEY=${OPENAI_API_KEY}
      - BLANKETAUDIT_NEO4J__URI=bolt://neo4j:7687
      - BLANKETAUDIT_NEO4J__USER=neo4j
      - BLANKETAUDIT_NEO4J__PASSWORD=${NEO4J_PASSWORD:-changeme}
      - BLANKETAUDIT_MILVUS__URI=http://milvus:19530
      - BLANKETAUDIT_DB__URL=postgresql://blanketaudit:${DB_PASSWORD:-changeme}@postgres:5432/blanketaudit
    volumes:
      - scan-data:/data
    depends_on:
      - neo4j
      - milvus
      - postgres
    restart: unless-stopped
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8000/api/health"]
      interval: 30s
      timeout: 10s
      retries: 3

  # ── Neo4j (Call Graph + Knowledge Graph) ──
  neo4j:
    image: neo4j:5-community
    ports:
      - "7474:7474"             # Browser UI
      - "7687:7687"             # Bolt protocol
    environment:
      - NEO4J_AUTH=neo4j/${NEO4J_PASSWORD:-changeme}
      - NEO4J_PLUGINS=["apoc"]
      - NEO4J_server_memory_heap_max__size=1G
    volumes:
      - neo4j-data:/data
    restart: unless-stopped

  # ── Milvus (Vector DB for Semantic Search) ──
  milvus:
    image: milvusdb/milvus:v2.4-latest
    ports:
      - "19530:19530"           # gRPC
      - "9091:9091"             # Metrics
    environment:
      - ETCD_USE_EMBED=true
      - COMMON_STORAGETYPE=local
    volumes:
      - milvus-data:/var/lib/milvus
    restart: unless-stopped

  # ── PostgreSQL (Scan History + API State) ──
  postgres:
    image: postgres:16-alpine
    ports:
      - "5432:5432"
    environment:
      - POSTGRES_USER=blanketaudit
      - POSTGRES_PASSWORD=${DB_PASSWORD:-changeme}
      - POSTGRES_DB=blanketaudit
    volumes:
      - postgres-data:/var/lib/postgresql/data
    restart: unless-stopped

  # ── Next.js Web UI ──
  web:
    build:
      context: ./web
      dockerfile: Dockerfile
    ports:
      - "3000:3000"
    environment:
      - NEXT_PUBLIC_API_URL=http://localhost:8000
    depends_on:
      - api
    restart: unless-stopped

volumes:
  scan-data:
  neo4j-data:
  milvus-data:
  postgres-data:

On-Premises with Ollama (Zero Cloud)

For air-gapped environments and organizations that cannot send code to external APIs. Everything runs on your servers, including the LLM.

# Start the on-prem stack with GPU-accelerated Ollama
docker compose -f docker-compose.onprem.yml up -d

# No API keys needed. No data leaves your network.
# Ollama with GPU passthrough for fast local inference.

docker-compose.onprem.yml

version: "3.9"

services:

  api:
    build:
      context: .
      dockerfile: Dockerfile.api
    ports:
      - "8000:8000"
    environment:
      - BLANKETAUDIT_LLM__PROVIDER=ollama
      - BLANKETAUDIT_LLM__MODEL=llama3.1
      - BLANKETAUDIT_LLM__BASE_URL=http://ollama:11434
      - BLANKETAUDIT_EMBEDDING__PROVIDER=ollama
      - BLANKETAUDIT_EMBEDDING__MODEL=nomic-embed-text
      - BLANKETAUDIT_NEO4J__URI=bolt://neo4j:7687
      - BLANKETAUDIT_NEO4J__USER=neo4j
      - BLANKETAUDIT_NEO4J__PASSWORD=${NEO4J_PASSWORD:-changeme}
      - BLANKETAUDIT_MILVUS__URI=http://milvus:19530
      - BLANKETAUDIT_DB__URL=postgresql://blanketaudit:${DB_PASSWORD:-changeme}@postgres:5432/blanketaudit
    depends_on:
      - ollama
      - neo4j
      - milvus
      - postgres
    restart: unless-stopped

  # ── Ollama with GPU Passthrough ──
  ollama:
    image: ollama/ollama:latest
    ports:
      - "11434:11434"
    volumes:
      - ollama-models:/root/.ollama

    restart: unless-stopped

  neo4j:
    image: neo4j:5-community

    environment:

    volumes:

    restart: unless-stopped

  milvus:
    image: milvusdb/milvus:v2.4-latest
    ports:
      - "19530:19530"
    volumes:
      - milvus-data:/var/lib/milvus
    restart: unless-stopped

  postgres:
    image: postgres:16-alpine
    environment:
      - POSTGRES_USER=blanketaudit
      - POSTGRES_PASSWORD=${DB_PASSWORD:-changeme}
      - POSTGRES_DB=blanketaudit
    volumes:
      - postgres-data:/var/lib/postgresql/data
    restart: unless-stopped

  web:
    build:
      context: ./web
      dockerfile: Dockerfile
    ports:
      - "3000:3000"
    environment:
      - NEXT_PUBLIC_API_URL=http://localhost:8000
    depends_on:
      - api
    restart: unless-stopped

  ollama-models:
  neo4j-data:
  milvus-data:
  postgres-data:
  scan-data:

After starting, pull the models into the Ollama container:

# Pull models into the running Ollama container
docker compose -f docker-compose.onprem.yml exec ollama ollama pull llama3.1
docker compose -f docker-compose.onprem.yml exec ollama ollama pull nomic-embed-text

Railway Deployment (Cloud API)

Deploy the API server to Railway in under 5 minutes. Railway auto-detects the Dockerfile and handles TLS, scaling, and logging.

Step-by-Step

  1. Fork the repo on GitHub (or use your own clone).
  2. Create a new Railway project at railway.app/new.
  3. Connect your GitHub repo. Railway detects Dockerfile.api automatically.
  4. Add a PostgreSQL service from the Railway marketplace (one click).
  5. Set environment variables in the Railway dashboard: 
    BLANKETAUDIT_LLM__PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-...
BLANKETAUDIT_DB__URL=${{Postgres.DATABASE_URL}}
BLANKETAUDIT_EMBEDDING__PROVIDER=openai
OPENAI_API_KEY=sk-...
  6. Deploy. Railway builds and deploys automatically. You get a public URL like https://blanketaudit-api-production.up.railway.app.
  7. Verify: Visit /docs on your Railway URL for the Swagger UI.
Cost: Railway's Hobby plan ($5/month) is sufficient for small teams. The API uses minimal resources when idle. LLM costs are separate (paid to Anthropic/OpenAI).

Vercel Deployment (Frontend)

Deploy the Next.js web UI to Vercel for a polished dashboard experience.

  1. Connect the web/ directory to a new Vercel project.
  2. Set the root directory to web in Vercel project settings.
  3. Add environment variable: 
    NEXT_PUBLIC_API_URL=https://your-railway-url.up.railway.app
  4. Deploy. Vercel handles builds, CDN, and preview deployments for PRs.

GitHub Action Setup

Run BlanketAudit in your CI/CD pipeline. Scan on every push or PR, upload SARIF results to GitHub Code Scanning, and fail the build on critical findings.

# .github/workflows/blanketaudit.yml
name: BlanketAudit Security Scan

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

permissions:
  contents: read
  security-events: write     # Required for SARIF upload

jobs:
  audit:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Run BlanketAudit
        uses: tectoniclabs/blanketaudit-action@v1
        with:
          # Scan configuration
          path: "."
          framework: "hipaa,soc2"
          domain: "healthcare"

          # LLM provider (optional — static-only if omitted)
          llm-provider: "anthropic"
          llm-model: "claude-sonnet-4-20250514"

          # Cost controls
          max-cost-usd: "2.00"
          token-budget: "300000"

          # Fail the build on critical findings
          fail-on-critical: "true"
          fail-on-high: "false"

          # Output formats
          output-formats: "sarif,json"
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}

      - name: Upload SARIF to GitHub Code Scanning
        uses: github/codeql-action/upload-sarif@v3
        if: always()
        with:
          sarif_file: blanketaudit-report.sarif

      - name: Upload report artifacts
        uses: actions/upload-artifact@v4
        if: always()
        with:
          name: blanketaudit-report
          path: |
            blanketaudit-report.json
            blanketaudit-report.sarif
Tip: For PRs, use fail-on-critical: "true" to block merges with critical vulnerabilities. For main branch scans, set both to "false" and use the SARIF upload for tracking trends.

Production Checklist

Before going live, verify every item on this list.

Security

[ ]API keys stored in a secrets manager (not environment variables in plain text)
[ ]HTTPS enabled on all public endpoints (use a reverse proxy like Caddy or nginx)
[ ]Neo4j password changed from default
[ ]PostgreSQL password changed from default
[ ]API authentication configured (API key or OAuth)
[ ]Network: Neo4j, Milvus, PostgreSQL not exposed to public internet

Cost Controls

[ ]max_scan_cost_usd set to a reasonable limit per scan
[ ]token_budget_per_agent configured (default: 500K tokens)
[ ]LLM provider billing alerts configured (Anthropic/OpenAI dashboard)
[ ]Rate limiting enabled on the API (prevent runaway scans)

Monitoring

[ ]Prometheus scraping the /metrics endpoint
[ ]Grafana dashboards configured for scan duration, token usage, error rate
[ ]Alerting on: scan failures, circuit breaker open, cost threshold exceeded
[ ]OpenTelemetry traces exported to Jaeger/Zipkin (optional but recommended)
[ ]Log aggregation configured (structlog JSON output to ELK/Loki)

Data

[ ]Docker volumes mounted to persistent storage (not ephemeral container storage)
[ ]PostgreSQL backup schedule configured (daily recommended)
[ ]Neo4j backup schedule configured
[ ]Scan history retention policy set (e.g., keep last 90 days)
[ ]Temp directory cleanup verified (atexit handler + cron fallback)

Availability

[ ]Health check endpoints verified for all services
[ ]Restart policies set to unless-stopped or always
[ ]Memory limits configured per container (prevent OOM on large scans)
[ ]Graceful shutdown: API drains in-progress scans before stopping
