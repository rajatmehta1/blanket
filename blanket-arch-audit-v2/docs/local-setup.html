Local Setup & Ollama Guide quickstart

Get BlanketAudit running on your machine in under 5 minutes. No Docker required. Choose your LLM provider—or run with zero AI for free static-only scans.

Prerequisites

DependencyRequired?Purpose
Python 3.11+requiredRuntime for the entire application
GitrequiredClone repos, compute diffs for incremental scanning
pip or uvrequiredInstall Python packages
OllamaoptionalFree local LLM inference (no API keys needed)
SemgrepoptionalStatic analysis (SAST). BlanketAudit uses built-in rules if missing.
GitleaksoptionalSecret detection in source code and git history
Node.js 18+optionalOnly needed if running the web frontend

Installation (No Docker)

Clone and install BlanketAudit as an editable Python package. All dependencies are declared in pyproject.toml.

# Clone the repository
git clone https://github.com/tectoniclabs/blanketaudit
cd blanketaudit

# Create a virtual environment (recommended)
python -m venv .venv
source .venv/bin/activate   # Linux/macOS
.venv\Scripts\activate      # Windows

# Install in editable mode with all dependencies
pip install -e .

# Verify installation
blanketaudit --version
# BlanketAudit v2.0.0
Tip: If you prefer uv for faster installs, run uv pip install -e . instead. It resolves dependencies 10-100x faster than pip.

Running with No LLM (Static Only, Free)

BlanketAudit works out of the box with zero AI, zero API keys, zero cost. Static scanners (Semgrep, Gitleaks, OSV, regex policies) run deterministically and produce actionable findings.

# Scan a local project — static only, no LLM calls
blanketaudit scan ./my-project

# Scan with a specific compliance framework
blanketaudit scan ./my-project --framework hipaa

# Scan multiple repos at once
blanketaudit scan ./patient-api ./payment-engine ./portal-web

# Dry run: see what would be scanned + cost estimate
blanketaudit scan ./my-project --dry-run

Output formats are generated automatically:

  • report.pdf — Dark-themed PDF with all 9 sections
  • report.html — Interactive HTML with expandable findings
  • report.json — Machine-readable for CI/CD integration
  • report.sarif — GitHub/IDE code scanning integration

Running with Ollama (Local AI, Free)

Ollama gives you AI-powered analysis without paying for API keys. Models run entirely on your machine. BlanketAudit supports Ollama as a first-class provider through LangChain.

Step 1: Install Ollama

# Linux / macOS
curl -fsSL https://ollama.ai/install.sh | sh

# Windows — download from https://ollama.ai/download
# Or via winget:
winget install Ollama.Ollama

# Verify Ollama is running
ollama --version

Step 2: Pull Models

You need one LLM for analysis and one embedding model for semantic search.

# Pull the LLM (pick one based on your hardware)
ollama pull llama3.1           # 8B params, ~5GB, works on 8GB RAM
ollama pull llama3.1:70b       # 70B params, ~40GB, needs 64GB+ RAM
ollama pull deepseek-coder-v2  # Code-specialized alternative

# Pull the embedding model
ollama pull nomic-embed-text   # Fast, high-quality embeddings
ModelSizeRAM NeededBest For
llama3.14.7 GB8 GBGeneral analysis, fast
llama3.1:70b40 GB64 GBHighest quality local analysis
deepseek-coder-v28.9 GB16 GBCode-focused tasks
nomic-embed-text274 MB1 GBEmbeddings for semantic search

Step 3: Configure BlanketAudit

# Set environment variables
export BLANKETAUDIT_LLM__PROVIDER=ollama
export BLANKETAUDIT_LLM__MODEL=llama3.1
export BLANKETAUDIT_EMBEDDING__PROVIDER=ollama
export BLANKETAUDIT_EMBEDDING__MODEL=nomic-embed-text

# Optional: Ollama runs on localhost:11434 by default
# Change only if you run Ollama on a different host
export BLANKETAUDIT_LLM__BASE_URL=http://localhost:11434

Step 4: Run a Scan with AI

# Full AI-powered scan with compliance framework
blanketaudit scan ./my-project --domain healthcare --framework hipaa

# Multi-framework scan
blanketaudit scan ./my-project --framework hipaa --framework soc2 --framework pci-dss

# Limit token budget (useful for slower hardware)
blanketaudit scan ./my-project --max-tokens 200000
Performance note: On a MacBook Pro M2 with 16GB RAM, llama3.1 processes about 30 tokens/sec. A typical 500-file scan takes 8-15 minutes with AI enabled vs 30-60 seconds static only.

Running with Cloud LLMs

For the highest quality analysis, use a cloud LLM provider. Each provider is accessed through LangChain abstractions—you only need to set environment variables.

Anthropic (Claude)

export BLANKETAUDIT_LLM__PROVIDER=anthropic
export BLANKETAUDIT_LLM__MODEL=claude-sonnet-4-20250514
export ANTHROPIC_API_KEY=sk-ant-...
# Compliance agent automatically uses Claude Opus for deeper reasoning

OpenAI (GPT-4)

export BLANKETAUDIT_LLM__PROVIDER=openai
export BLANKETAUDIT_LLM__MODEL=gpt-4o
export OPENAI_API_KEY=sk-...

Groq (Ultra-Fast Inference)

export BLANKETAUDIT_LLM__PROVIDER=groq
export BLANKETAUDIT_LLM__MODEL=llama-3.1-70b-versatile
export GROQ_API_KEY=gsk_...

Google (Gemini)

export BLANKETAUDIT_LLM__PROVIDER=google
export BLANKETAUDIT_LLM__MODEL=gemini-pro
export GOOGLE_API_KEY=...

Azure OpenAI (Enterprise)

export BLANKETAUDIT_LLM__PROVIDER=azure
export BLANKETAUDIT_LLM__MODEL=gpt-4
export AZURE_OPENAI_ENDPOINT=https://your-resource.openai.azure.com/
export AZURE_OPENAI_API_KEY=...
export AZURE_OPENAI_DEPLOYMENT_NAME=gpt-4

Configuration File (audit.yaml)

For persistent configuration, create an audit.yaml file in your project root or pass it with --config. This is the recommended approach for teams.

# audit.yaml — BlanketAudit scan configuration

# ── Project Metadata ──
project:
  name: "MedPay"
  tagline: "Patient Insurance Payment Platform"
  domain: "healthcare"            # healthcare | fintech | ecommerce | saas

# ── Repositories to Scan ──
repos:
  - path: "./patient-api"
  - path: "./payment-engine"
  - path: "./portal-web"
  # Remote repos are cloned automatically:
  # - url: "https://github.com/org/repo.git"

# ── Compliance Frameworks ──
compliance:
  frameworks:
    - "hipaa"                   # HIPAA Security Rule
    - "soc2"                    # SOC 2 Trust Service Criteria
    - "pci-dss"                 # PCI-DSS v4.0
  # - "gdpr"                    # GDPR (EU)

# ── LLM Provider ──
llm:
  provider: "ollama"            # anthropic | openai | ollama | groq | google | azure | none
  model: "llama3.1"             # Default model for most agents
  base_url: "http://localhost:11434"  # Only needed for Ollama / custom endpoints
  per_agent_models:             # Override model per agent (optional)
    compliance: "llama3.1:70b"  # Use larger model for compliance reasoning
    security: "llama3.1"
    architecture: "llama3.1"
    quality: "llama3.1"

# ── Embeddings ──
embedding:
  provider: "ollama"           # openai | ollama | huggingface | voyage | none
  model: "nomic-embed-text"

# ── Cost Controls ──
cost:
  max_scan_cost_usd: 5.00      # Hard abort if projected cost exceeds this
  token_budget_per_agent: 500000  # Max tokens per agent before fallback to static
  dry_run: false               # Set true to estimate cost without scanning

# ── Output ──
output:
  formats:
    - "pdf"                    # Dark-themed WeasyPrint PDF
    - "html"                   # Interactive HTML report
    - "json"                   # Machine-readable JSON
    - "sarif"                  # GitHub / IDE integration
  directory: "./reports"        # Output directory

# ── Caching ──
cache:
  enabled: true                # SHA-256(content + policy_version) cache
  directory: ".blanketaudit-cache"

# ── Static Tools ──
tools:
  semgrep:
    enabled: true
    extra_rules: []             # Paths to additional Semgrep rule files
  gitleaks:
    enabled: true
  osv:
    enabled: true

Running Tests

# Install test dependencies
pip install -e ".[test]"

# Run all unit tests (fast, no LLM calls)
python -m pytest tests/unit/ -v
# 1,565 tests pass in ~25 seconds

# Run fixture tests (planted vulnerabilities)
python -m pytest tests/fixtures/ -v

# Run golden file tests (expected output comparison)

# Run everything except LLM-as-Judge eval
python -m pytest tests/ -k "not TestLLMJudge"

# Run with coverage report
python -m pytest tests/ --cov=codeaudit --cov-report=html

Troubleshooting

WeasyPrint: Missing GTK Libraries

WeasyPrint requires GTK/Pango system libraries for PDF rendering.

# Ubuntu / Debian
sudo apt install libpango-1.0-0 libpangocairo-1.0-0 libgdk-pixbuf2.0-0 libffi-dev

# macOS
brew install pango gdk-pixbuf libffi

# Windows — install GTK3 runtime:
# https://github.com/nickvdyck/weasyprint-win/releases
# Or use: pip install weasyprint (bundled DLLs on newer versions)

Tree-sitter: Compilation Errors

Tree-sitter grammars are compiled from C. You need a C compiler available.

# Ubuntu / Debian
sudo apt install build-essential

# macOS (Xcode CLI tools)
xcode-select --install

# Windows (install Visual Studio Build Tools)
# https://visualstudio.microsoft.com/visual-cpp-build-tools/

Ollama: Connection Refused

If BlanketAudit cannot reach Ollama, make sure the service is running.

# Check if Ollama is running
curl http://localhost:11434/api/tags

# Start Ollama (Linux)
ollama serve

# On macOS, Ollama runs as a system service after install
# On Windows, start the Ollama app from the Start Menu

# If using a remote Ollama instance:
export BLANKETAUDIT_LLM__BASE_URL=http://your-server:11434

Semgrep / Gitleaks Not Found

These tools are optional. BlanketAudit falls back to built-in regex rules if they are missing. To install:

# Semgrep
pip install semgrep
# Or: brew install semgrep

# Gitleaks
brew install gitleaks
# Or download from: https://github.com/gitleaks/gitleaks/releases

Out of Memory During Scan

Large codebases can use significant memory during AST parsing and call graph construction.

# Reduce token budget to limit memory usage
blanketaudit scan ./large-project --max-tokens 100000

# Scan specific directories instead of entire repo
blanketaudit scan ./large-project/src/api ./large-project/src/auth

# Disable vector DB (reduces memory by ~500MB)
export BLANKETAUDIT_EMBEDDING__PROVIDER=none

Permission Errors on Temp Files

BlanketAudit creates temporary directories for cloned repos and intermediate results. If the process crashes, stale temp dirs may remain.

# Clean up stale temp directories
blanketaudit cleanup

# Or manually:
rm -rf /tmp/blanketaudit-*
